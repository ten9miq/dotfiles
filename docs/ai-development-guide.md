# AI 開発ガイド

## プロジェクト概要

このリポジトリは、複数のシェルやツールの設定をホームディレクトリへ配置するための dotfiles 集である。
ルートの `setup.sh` は `setup_env.sh` を読み込み、次のディレクトリにあるシェルスクリプトを並列実行する。

- `bash/`: Bash の設定
- `zsh/`: Zsh の設定
- `fish/`: Fish の設定
- `shell_common/`: Bash と Zsh で共有する設定
- `vim/`: Vim、GVim の設定
- `tmux/`: tmux の設定
- `ssh/`: SSH クライアント設定
- `git/`: Git 設定
- `bin/`: ユーザーコマンドと fzf の配置
- `etc/`: その他のホームディレクトリ向け設定
- `windows/`: Windows 固有の設定

多くの `init.sh` は自身の位置から `../setup_env.sh` を読み込み、リポジトリ内のファイルを `$HOME` 以下へコピーする。
`setup_env.sh` は共通関数、OS判定、バックアップ付き `cp` を提供する。

## 変更時の判断基準

### 配置先と構成

- 新しい設定対象を追加する場合は、既存ディレクトリの責務に収まるかを先に確認する。
- 新しいトップレベルディレクトリを `setup.sh` の `dists` に追加すると、その配下の `*.sh` が並列実行されることを考慮する。
- `init.sh` がコピー対象に自分自身を含めない既存パターンを維持する。
- 共通処理は `setup_env.sh`、シェル横断の設定は `shell_common/` を第一候補とする。
- マシン固有・利用者固有の値を、共有される dotfiles に固定しない。

### シェルコード

- シバンと対象シェルを一致させ、Bash 固有構文を POSIX `sh` 用ファイルへ持ち込まない。
- パスや引数を扱う新規コードでは、空白やグロブ展開を避けるため `"$var"` 形式を基本とする。
- コマンドの存在確認やOS判定には、既存の `has`、`os_type` などの共通関数を再利用する。
- 並列実行されても他の初期化処理と競合しないようにする。
- 外部ダウンロードを追加する場合は、取得元、失敗時の挙動、再実行時の安全性を明確にする。可能ならバージョンや検証方法を固定する。

### 秘密情報とローカル設定

- SSH秘密鍵、APIキー、Cookie、トークン、パスワードをコミットしない。
- Gitのユーザー情報など個人差のある設定は、追跡対象外のローカルファイルから読み込む設計にする。
- サンプルが必要な場合は架空の値を使い、実値を入れる場所と管理方法を説明する。

## 推奨する検証手順

変更範囲に応じて、次の順で確認する。

1. 差分を読み、意図しないファイルや個人情報が含まれていないことを確認する。
2. Bash ファイルに `bash -n path/to/file.sh` を実行する。
3. ShellCheck が利用可能なら `shellcheck path/to/file.sh` を実行する。
4. Zsh/Fish 固有ファイルは、対応シェルの構文確認機能を使う。
5. 配置処理は一時ホームを使い、生成されたファイル、権限、リンク、再実行時の挙動を確認する。

隔離テストでは、実ユーザーのホーム、Git設定、SSH設定を変更しないこと。ネットワーク取得を含む `bin/init.sh` などは、構文確認だけで十分か、依存部分を分離して検証できるかを先に判断する。

## 完了条件

- 依頼された変更が必要なOS・シェルに対して矛盾なく反映されている。
- 構文確認または同等の検証が完了している。
- ホームディレクトリや秘密情報に意図しない変更がない。
- 新しい運用知識が必要な場合は `docs/` の関連文書も更新されている。
- 未検証事項と互換性上の注意点が作業報告に記載されている。
